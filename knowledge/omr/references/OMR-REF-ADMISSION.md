# OMR 考号与条码异常分类及排查顺序

来源为《考号填涂异常专项分析》《OMR-智批-问题排查》及 I 类问题台账。本文提炼可复用分类，不复制原始考号、学生信息、工单标识、图片签名链接或完整业务请求。

## OMR 考号异常先区分识别与匹配

识别引擎返回的号码、业务侧学生关系及名册匹配是不同层。定位失败、未读出号码、号码读错、读对但匹配不到学生，要先分别确认。

Java 扫描仓库没有证明自己负责考试创建和名册维护。扫错学校/学科或上游学生关系问题，不直接认定为 OMR 算法故障。

## OMR 考号区域偏移或裁剪不完整

检查实际工作图、模板图及坐标系，再核对区域边界、首框、行列数和间距。缩印、模板与印刷布局不一致、周边框线干扰可能影响定位；四角对齐也不证明内部布局一致。

把问题归为“模板坐标错”前，应做独立几何对照。I01/I02 等案例中的裁窄或偏移仅针对特定样本，不能统一给所有模板套值。

## OMR 打印、填涂与图像质量

背景或框线偏淡、残缺、过浓、压缩失真、周边噪声都可能影响检测。要以同次裁图、实际输入模板和对应库版本检查最终采样区域及识别结果，不能只看原纸或界面截图。

旧案例中“打印问题”的初步判断不是已确认的上游责任。需要原始印刷文件、原始采集和后处理结果才能区分具体来源。

## OMR 自定义考号与业务规则

源文档记录过自定义后四位/后三位、手写姓名或号码与业务匹配相关的问题。这些应作为历史规则和缺陷线索，而不是直接宣布当前所有版本仍有同一缺陷。

固定本次考试及来源，分别核对模板配置、引擎输出和上游匹配规则；修正卡型或名册规则前，不能仅凭其他案例的临时处理下结论。

## OMR 条码失败与默认错误字段

I04 记录 Java 客户端默认 errorCode=0 但实际无 result 的历史传播问题。判断条码成功时要核对真实 RPC ret 和有效号码，不能只看默认字段。

条码库 ret=2 的独立含义也不能套通用 OMR 码 2。I03 的条纹比例失真是另一层图像问题，不能把两类机制混为同一个原因。

## OMR 考号问题的证据与处置

优先收集必要的接口、卡型、识别模式、模板/工作图对应关系、原始返回码、号码是否为空以及后续匹配状态。记录可复用事实时移除学生信息和可访问原图的签名链接。

临时调整区域、多模板重识别和业务后台处理要保留验证范围。源文档“初步设计”里的异常页拖动坐标、保存主卡或子模板方案不能直接描述为当前已上线功能。
